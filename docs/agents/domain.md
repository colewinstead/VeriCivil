# Domain docs

## Layout

Use one root `GLOSSARY.md` and `docs/adr/` for architectural decisions.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the work.
If these files are absent, proceed silently. Domain-modeling work creates
them when terminology or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, check existing project language before
proposing a glossary addition.

## Decisions

Surface conflicts with existing ADRs explicitly, identifying the ADR
and explaining why the decision may need reconsideration.
